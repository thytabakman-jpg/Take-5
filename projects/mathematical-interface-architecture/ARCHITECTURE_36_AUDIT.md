## Strongest findings

### Eight core artifact roles are justified

The audit repeatedly exposes eight distinct jobs

1. Project Charter
2. Canonical Model
3. Presentation Invariant
4. Artifact Registry
5. Currentness and Source Manifest
6. Friction and Gap Ledger
7. Validation Contract
8. Operating SOP

No 36-cell residual currently forces a ninth core semantic role.

### Supporting artifacts are not core roles

Rendered assets, schemas, tests, audit reports, runtime implementations, migration records, and benchmark fixtures support the eight roles.

They are added when demanded by the object.

### Highest-risk cells

The historical friction clusters in

- INTERFACE × COUPLE
- CROSS_LAYER × COUPLE
- CROSS_LAYER × ISOLATE
- BOUNDARY × CONTRACT
- SYSTEM × OUTWARD
- COMPONENT × ISOLATE

These correspond directly to

- semantic color not reaching rendered color
- math changing during layout work
- semantic success being mistaken for rendering success
- currentness conflicts across repositories and candidates
- raw rendering syntax appearing in user-visible output
- artifact identity and filename/version mismatch

## Architecture decision

Do not create one giant Mathematical Interface Architecture document.

Use one project with eight non-collapsed core artifact roles connected by an explicit registry.

The registry is the navigation and dependency surface.

The charter owns project identity.

The canonical model owns mathematics.

The presentation invariant owns visible status rules.

The currentness manifest owns source and version control.

The friction ledger owns unresolved defect classes.

The validation contract owns acceptance.

The SOP owns repeatable operation.

No artifact self-expands its authority into another role.

## Reentry rule

A material change to any of the following reopens the affected artifact cone

- mathematical object
- version identity
- reconstruction status
- renderer behavior
- source authority
- currentness
- artifact role
- validation result
- project scope

Closure is basis-relative and requires registry consistency plus all four validation gates.
