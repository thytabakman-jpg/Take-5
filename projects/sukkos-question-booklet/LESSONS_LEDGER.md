# Lessons Ledger

Status: APPEND-ONLY

## L001 Separate representation from authority

Failure pattern:
a later file or render becomes "the latest" and silently replaces the actual accepted object.

Protection:
authority is explicit in AUTHORITY_REGISTRY.md.
Recency alone has no authority.

## L002 One giant document causes overwrite

Failure pattern:
copy, philosophy, learner state, sources, art, and project control are edited in the same surface.

Protection:
one canonical owner per load-bearing dimension plus cross-file references.

## L003 Coverage is not content ownership

Failure pattern:
a 36-dimensional audit result gets mistaken for the canonical object.

Protection:
coverage cells are evidence-only. Canonical files own truth.

## L004 Math cannot smuggle an ought

Failure pattern:
a descriptive scientific or mathematical relation is turned directly into a human or Jewish norm.

Protection:
IS_OUGHT_BOUNDARY.md owns the bridge.

## L005 Holiday mention is not holiday embodiment

Failure pattern:
Sukkos can be replaced with a generic activity with no educational loss.

Protection:
SUKKOS_EMBODIMENT.md requires holiday surplus and replacement failure.

## L006 Teacher explanation can hide artifact failure

Failure pattern:
the booklet only works because an adult supplies the missing conceptual bridge.

Protection:
all required content and handoffs are public.

## L007 Correct local pages can form a broken booklet

Failure pattern:
each page looks successful alone while the handoffs fail.

Protection:
page-level QA and whole-booklet causal QA remain separate.

## L008 Copy-first design hides unresolved objects

Failure pattern:
polished wording creates a false sense that the underlying model is settled.

Protection:
exact copy opens only after route and model gates pass.

## L009 Tool names are not tool recovery

Failure pattern:
a named tool is invoked as a vague compressed prompt and loses wrapper, geometry, or protected behavior.

Protection:
tool application records cite current Take-5 contracts and type unavailable runtime evidence.

## L010 Learn at the moment of failure

Failure pattern:
lessons are reconstructed days later from chat fragments.

Protection:
every material failure creates a ledger entry before the affected workstream closes.

## L011 Prose dependencies are not enough

Failure pattern:
a lifecycle says that one object depends on another, but no single graph controls reentry.

Protection:
DEPENDENCY_GRAPH.md makes reopening behavior explicit.

## L012 OPEN can become permanent fog

Failure pattern:
design coordinates remain OPEN after enough evidence exists to decide them.

Protection:
once evidence discriminates the candidates, commit the route and preserve reopening conditions rather than carrying fake uncertainty.

## L013 A model activity can blur halachic identity

Failure pattern:
a craft shaped like a sukkah is mistaken for a halachically valid sukkah.

Protection:
edible construction is separated from the source-grounded s'chach classification task and labelled only as a model.

## L014 Missing information is pedagogically useful

Discovery:
the strongest Page 3 state is not a card with a known answer but a card that cannot be classified until the learner asks for one missing fact.

Protection:
preserve the mystery branch and its missing attachment status through render and repair.
