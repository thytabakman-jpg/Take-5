# Comparison — Current IC118 vs Favored-Behavior Successor

Status: CURRENT ANALYSIS

## Current Reaserch IC118

Current canonical role:
completion-enforcement controller.

Strengths:
- distinguishes live residual from certified terminal boundary;
- refuses unresolved release while candidate work remains;
- carries exact reopen conditions;
- uses ImprovementCore as solver child;
- preserves execution truth and independent challenge.

What it does not itself encode as first-class protected behavior:
- Semantic x Runtime x Authority reality triad;
- state-relative nondominated route selection;
- cheap-direct-path preference;
- structural/project stewardship and owner separation;
- the broader "user does not script the internal route" effectiveness profile.

Those behaviors can be delegated, but the current IC118 identity does not make the complete bundle
visible as one effectiveness contract.

## Recovered favored behavior

Evidence supports a broader user-valued profile:

1. reality separation;
2. adaptive state-relative selection;
3. reduced irrelevant work;
4. preserved plurality;
5. structural stewardship;
6. parent-goal continuity;
7. completion enforcement;
8. execution truth;
9. result-sensitive recurrence;
10. internal autonomy.

## Design decision

Do not mutate current IC118 into a monolithic solver/project manager.

Create an effectiveness profile above/beside the current IC118 completion core.

The profile declares the protected behavior and required owners; underlying responsibilities remain
with ProjectManager, ImprovementCore, ICC128, RealityGate and HF2.

This preserves why the experience was effective without recreating the old naming ambiguity.
