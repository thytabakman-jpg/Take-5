# Recovered Favored Behavior and Successor Design

Status: CANDIDATE / EVIDENCE-BACKED / NOT YET PROMOTED

## Core finding

There is no evidence-supported single historical formal object that can be truthfully identified as
"the awesome ICC118."

Instead, the 118 label accumulated several behaviors the user repeatedly selected when ordinary
ImprovementCore felt too lossy, too passive, too infrastructure-bound, or too willing to stop.

The supported bundle is:

1. Reality separation
   Semantic availability, runtime availability and authority are independent coordinates.
   A runtime failure must not erase a semantic capability.

2. State-relative routing
   Choose the next mathematical/project problem from the current state and new result, rather than
   blindly execute a fixed historical stage battery.

3. Cheap direct path
   When one preserving route dominates a broader route, use the smaller route.

4. Nondominated plurality
   Preserve incomparable live routes instead of forcing an invented scalar winner.

5. Structural stewardship
   Separate semantic substrate, job-level mathematics, system algebra, project state, evidence,
   authority and runtime. Do not overwrite one dimension because another changed.

6. Parent-goal continuity
   A child tool success, artifact write or local repair does not become project completion.

7. No premature unresolved release
   OPEN/BLOCKED/CONFLICT are internal states, not automatic user-terminal states when licensed work
   can still resolve them.

8. Execution truth
   Plan, semantic availability, artifact existence and actual execution are distinct.

9. Result-sensitive recurrence
   Material state change recomputes the frontier; unchanged reruns do not count as progress.

10. Internal autonomy
    The user supplies the goal, not a manual internal tool sequence.

## Why it felt better

The bundle reduces two forms of friction simultaneously:

- cognitive friction: fewer irrelevant stages, fewer false collapses, more direct work on the live
  distinction;
- management friction: the system keeps ownership of continuation, preserves evidence/authority,
  and does not hand the user a list of residuals it could still attack itself.

That combination is more important than the numeric label.

## Candidate architecture

Do not make one giant new primitive.

Use a successor profile:

ICC118 Effective Steward
=
CompletionEnforcer
∘ RealityGate
∘ StateRelativeSelector
∘ StewardshipGate

with delegated owners:

- ProjectManager owns project truth, owners, WBS, change, verification and evidence register.
- ImprovementCore owns substantive autonomous solving.
- ICC128/current routing owns endogenous question/work reselection where selected.
- IC118 owns response-release completion enforcement.
- RealityGate preserves Semantic x Runtime x Authority.
- HF2 owns same-capability recurrence.

The profile is a composition/policy surface, not a claim that all behaviors historically belonged
to one original ICC118 formal object.
