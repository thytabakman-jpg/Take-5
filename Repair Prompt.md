## 1. Governing objective

Improve the substantive quality, semantic precision, logical integrity and research value of every targeted document.

The tools are instruments for accomplishing this objective. Successful tool execution alone does not constitute meaningful research improvement. Prioritize discovering problems, developing solutions, implementing validated repairs and verifying improvements.

The user specifies the target documents when invoking the Repair skill. Targets may include individual files, multiple files, folders or combinations thereof.

Identify and verify the exact repository, folder paths and files included in the requested execution scope.

If the target documents are unambiguous, proceed directly. If the scope is ambiguous, obtain clarification before execution.

Process the target documents individually, following any execution order specified by the user.

Do not modify documents outside the established execution scope.

## 4. Adapted document semantic preflight

Apply the Semantic Preflight Protocol's every-word rule to the entire file, rather than merely its controlling question.

The original protocol is a provisional prompt-intake protocol. This document-wide application is an authorized adaptation, not an already certified native execution profile.

Examine every word, phrase, sentence, paragraph, heading, table, quotation, mathematical expression and analytical conclusion.

Classify non-load-bearing language without generating unnecessary commentary.

Examine all result-sensitive semantic coordinates, including:

- Object identity.
- Definitions.
- Predicates.
- Quantifiers.
- Modality.
- Temporal conditions.
- Scope and domain.
- Referents.
- Logical relations.
- Necessary and sufficient conditions.
- Explicit and implicit premises.
- Presuppositions.
- Ambiguities.
- Attribution.
- Source interpretation.
- Evidentiary strength.
- Inferential strength.
- Qualifications and exceptions.
- Claim-type classification.
- Historical versus current formulations.
- Terminological consistency.
- Redundancy and omitted distinctions.

Apply the mandatory mathematical object-integrity and prerequisite-integrity gates wherever formal or mathematical reasoning appears.

## 5. Document-specific requirements

For each document, establish whether:

1. Its purpose, governing questions and objectives are precisely formulated.
2. Its claims, arguments and analytical distinctions are clearly defined.
3. All relevant conditions, domains, meanings and temporal coordinates are fixed.
4. Its logical relationships and distinctions are valid.
5. The cited sources actually support their attributed claims.
6. Established, historical, reconstructed and exploratory claims remain distinguishable.
7. The conclusions follow from the available evidence.
8. Qualifications are preserved throughout the document.
9. Superseded formulations cannot contaminate current conclusions.
10. Analysis, significance and substantive contributions are defensible.
11. Discoveries are not confused with unsupported originality claims.
12. Material evidence, objections and unresolved questions are preserved.
13. The document's heading hierarchy accurately reflects the logical and organizational relationships between its sections.
14. Every heading accurately represents the content and function of its corresponding section.
15. The underlying Markdown or other document syntax correctly implements the intended heading levels, structural hierarchy and formatting.
16. All internal and external links resolve correctly, including file paths, URLs and section anchors.
17. Each link leads to the intended, relevant and current destination.
18. Links passing through obsolete placeholders, redundant redirects or unnecessary intermediary documents are replaced with direct links to their intended destinations.
19. Links to functional inventories, indexes, navigation hubs and other intermediary documents are preserved wherever those documents serve a substantive purpose.

Apply these requirements according to the document's purpose, content and function.

Where source evidence is insufficient, investigate the relevant external sources rather than manufacture a resolution.

## 7. Autonomous repair cycle

Complete the following cycle for each individual file before proceeding to the next.

1. Retrieve and freeze the current file version.
2. Read the entire document.
3. Conduct the comprehensive semantic preflight.
4. Execute the applicable native tools.
5. Consolidate discoveries and eliminate duplicate findings and false positives.
6. Investigate unresolved substantive problems.
7. Develop concrete textual and analytical repairs.
8. Assess each proposed repair using GO / NO-GO / TWEAK.
9. Refine TWEAK recommendations recursively.
10. Reject NO-GO recommendations.
11. Implement validated GO recommendations directly in GitHub.
12. Retrieve the modified document and verify the actual changes.
13. Re-examine affected passages and downstream dependencies for regressions.
14. Record any remaining material limitations.
15. Proceed immediately to the next file.

Use genuinely independent evaluation where available. If that capability is unavailable, distinguish same-context adversarial review from independent assessment and do not falsely claim the latter.

I authorize individual file repairs without requiring further approval. Preserve substantive research, source evidence, objections and useful exploratory material. These files are comprehensive research repositories, not condensed manuscript drafts.

## 8. Sequential execution and continuation

Work on one file at a time.

Finish, commit and verify each file before beginning the next. This ensures that completed improvements survive interruptions.

Do not stop after each file to request permission. Continue autonomously across all the files.

Maintain a compact continuation record containing completed file identifiers, verified commits, material findings, repairs, unresolved issues and the next file.

If interrupted by execution limits, resume from the first unfinished file using the current repository state.

## 9. Success criteria

Measure success primarily through:

- Substantive defects resolved.
- Logical and semantic precision improved.
- Evidence and attribution strengthened.
- Invalid inferences corrected.
- Valuable research discoveries established.
- Philosophical contributions improved.
- Existing research preserved.
- Repairs implemented and verified.

The number of tools executed is secondary.

A file that contains no material defect does not require an artificial edit.
