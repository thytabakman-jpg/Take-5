# Adaptive Inquiry Kernel

A clean transferable research/problem-solving control system distilled from the strongest
validated behavior in Take Two, Take Five, and the recovered ImprovementCore lineage.

This branch intentionally excludes project history and personal naming from the architecture.

## Core idea

The system combines five roles:

1. Kernel — protects semantic state, authority, transitions, OPEN, and verification.
2. Supervisor — reconstructs continuity/currentness without selecting substantive actions.
3. Controller — generates and selects result-sensitive continuation until typed termination.
4. Capability repertoire — typed operations selected by the controller rather than hard-coded into one giant loop.
5. Recovery — proves important behavior remains reconstructible and operational after changes.

## Operating law

Observe
-> Freeze / Type
-> Discover / Challenge
-> Diagnose when needed
-> Decide under authority
-> Transition
-> Verify
-> Observe
-> Reenter on material change.

Discovery can change the candidate object, relation, question, work, and capability universe.

## Design laws

- distinctions do not imply separate operating surfaces;
- views/compositions precede new registries and subsystems;
- evidence does not self-authorize mutation;
- consequential change uses a typed transition;
- OPEN and incomparability survive compression;
- selected is not executed; executed is not admitted; admitted is not consumed;
- internal continuation is controller-owned and result-sensitive;
- negative/no-gain evidence persists relative to its basis;
- capabilities migrate by behavior, not filenames;
- a successor must prove preserved behavior or expose an OPEN regression;
- no component self-promotes.

## Generic naming

The transferable architecture uses Supervisor / Controller / Kernel rather than Jane /
ImproveCore. Installations may assign their own names.
