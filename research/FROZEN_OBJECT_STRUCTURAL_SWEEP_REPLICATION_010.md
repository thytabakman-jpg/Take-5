## MTA preflight

The requested behavior is not ordinary audit and not ordinary optimization.

Freeze object X and boundary ∂X.
Suppress successor/repair/solution pressure during observation.
Run behaviors independently enough that each may expose consequences without being forced toward the current plan.
Accumulate raw structural returns.
Only after the sweep, reconcile relations, conflicts, higher-order residuals and action implications.

Formal operator:

FOSS(X,∂X,B)=Rec( { b(X | ∂X, Opt=0) : b∈B } )

Critical anti-contamination rule:
During b-runs, no output from an earlier behavior becomes a target/solution constraint for a later behavior. Cross-behavior synthesis occurs only in Rec.

This differs from 12-before/12-after. That protocol asks lenses to improve a live episode. FOSS asks them to observe a frozen object without pressure to improve it.

## Experiment A — entire Take-5 / Improvement Core project

Frozen object X_A:
Current Take-5 architecture, runtime, tests, campaign records, recovered capability universe, historical reconstruction obligation, execution evidence and migration boundary as of this experiment.

Boundary ∂X_A:
No migration.
No promotion.
No architecture rewrite during sweep.
No new substantive goal.
No requirement that a behavior produce a useful answer.
No optimization toward A5.
No assumption that current plan is correct.
No result from one behavior constrains later observations.

Behavior returns

01 Goal Spine
Structural return: project contains two coupled objects often spoken as one: epistemic/semantic successor architecture and evidence-producing realization campaign.

02 Architecture Analysis
Return: A5 eight-role semantic algebra and runtime realization are at different maturity levels. Several implementation obligations live outside role algebra.

03 MTA
Return: "capability recovered" has at least four non-equivalent predicates: represented, bound, fixture-executable, historically reconstructed.

04 PD/PDAudit
Return: current success predicates are locally defined per family but historical equivalence relation remains underspecified operationally.

05 Multi-Object
Return: major failures observed so far occur at interfaces: workflow×module path, job×runner substrate, registration×namespace, test invariant×new executable state.

06 Diagnosis/Root Cause
Return: recurring defect class is boundary invisibility, not merely missing functionality.

07 Artifact Reality
Return: project has improved at distinguishing artifact, execution and authority, but campaign documents still risk becoming narrative state unless machine-linked to receipts.

08 Orphan/Ghost/Conflict
Return: 73 tool files, 49 capabilities, 33 historical capabilities, 58 behavior families and named research methods overlap but do not yet share one identity/equivalence ledger.

09 Representation Attack
Return: family ordering ORIENT→MAP→ATTACK→... is useful execution representation but can falsely look like semantic dependency order.

10 Result Sensitivity
Return: many implementation details can vary without threatening eight-role semantics; historical reconstruction and no-bypass evidence are more result-sensitive than module layout.

11 RTC
Return: strict gain is currently demonstrated locally by better execution truth, not yet globally by successor-over-predecessor evidence.

12 HF/Reentry
Return: campaign has reentry, but failure/search memory is distributed across prose, commits and CI rather than one queryable state.

13 Corpus Navigation
Return: recovered repertoire remains high-recall rather than globally complete; long-tail project-local machinery is still OPEN.

14 TransferCore
Return: lessons from failures are being transferred into A5 semantics, but transfer receipts are not first-class runtime objects.

15 Consequence Closure
Return: execution-substrate discovery implies environment/schedulability belongs in realization model and readiness evidence beyond the immediate CI repair.

16 Raise-the-Ceiling
Return: strongest ceiling gain is not adding more named tools; it is making behavior activation and evidence consumption enforceable.

17 Holdout
Return: no true unfamiliar messy-corpus holdout has yet tested the reconstructed stack end-to-end.

18 Ablation
Return: role necessity has analytic support; executable role/operator ablation remains incomplete.

19 Authority/Execution Truth
Return: no migration bypass observed. Fixture-executable status is correctly weaker than historical reconstruction.

20 Zero-Request
Return: true zero-request tool sweep remains blocked/incomplete; prior attempt exposed host pre-execution failure rather than tool behavior.

### Reconciliation A

Independent returns cluster into five structural residuals:

RA1 Identity unification
Need one machine-readable ledger connecting tool files ↔ semantic capabilities ↔ behavior families ↔ historical capabilities ↔ executable programs ↔ receipts.

RA2 Boundary-first failure model
Most empirical defects are interface/boundary failures. Make boundary interaction a first-class validation dimension.

RA3 Historical equivalence
Need operational reconstruction relation before fixture completion can become preservation evidence.

RA4 Durable evidence state
Campaign state must become queryable machine state, not primarily prose + CI archaeology.

RA5 End-to-end unknown
Need messy holdout and true zero-request execution after sufficient family reconstruction.

No observation forces rejection of A5.

## Experiment B — current plan only

Frozen object X_B:
Current plan: MTA + selected 12 preflight → implement next capability family → CI → 12 postflight → reenter; family sequence ORIENT, MAP, ATTACK, GENERATE, IMPROVE, TRANSFER, VALIDATE; later historical regression, hard cases, closure, readiness.

Boundary ∂X_B:
Do not solve the project.
Do not alter A5.
Do not implement GENERATE during sweep.
Do not optimize the plan while observing it.
Behaviors return consequences only.

### Reconciliation B

The current plan is safe and productive but over-sequential.

Replace default selector:
Next = next family

with:
Next = ND(InformationGain, GoalImpact, ArchitectureRisk, HistoricalCoverage, Cost, AuthoritySafety)

Candidate frontier after reconciliation:
Q1 historical matched reconstruction relation + first matched case
Q2 machine-readable unified identity/evidence ledger
Q3 early cross-family interaction/ablation experiment
Q4 early zero-request/holdout experiment when runnable
Q5 continue GENERATE family

Do not automatically choose Q5 merely because it is next in registry order.

## Replication result

The method replicated its characteristic effect twice:
Whole-project sweep surfaced cross-cutting residuals not identical to current task.
Plan-only sweep changed the work selector itself.

The high-value mechanism appears to be:
Freeze + boundary + optimization suppression + independent returns + delayed reconciliation.

This is a candidate reusable behavior/tool. It is not yet promoted to canonical status. Replication count here: 2 frozen-object runs in this artifact; prior analogous observations exist but are not counted as these executions.
