# ImproveCore Run 091 — Recover Take-5 Intended End State

Date: 2026-09-26
Status: EXECUTED / MATERIAL STRICT GAIN / TARGET RECOVERED
Prompt: What was Take Five supposed to be? How can we get there?

## ASSERT / recovered target

Take-5 was intended to become the canonical cumulative autonomous
research/improvement system, not merely the fifth repository iteration.

The stable behavioral target across Take-2 through Take-5 is:

state/corpus
-> justified work
-> capability selection
-> real execution
-> verification
-> durable update
-> reselection/reentry
-> relative closure.

The strongest later formulation adds:
- small privileged kernel;
- durable reconstructible history;
- behavior-first capability system;
- Jane continuity interface;
- ImprovementCore adaptive manager;
- outside-tool/evidence routing;
- currentness/provenance/authority;
- automatic affected-cone propagation;
- anti-loss semantic lifecycle.

## PROBLEM

The current repository contains most major components, but they are not yet one
non-bypassable closed operating loop.

The dominant failure is not missing tool count.

It is integration continuity:

component exists
!=
ordinary entry reaches it
!=
result reaches the next consumer
!=
material delta reopens the correct dependency
!=
system continues without another user command.

## ROOT

The historical generator is fragmentation across control boundaries:

- entry state often arrives preconstructed;
- discoveries can fail to become executable work;
- selected child work can require caller-supplied handlers;
- state/history are not yet fully event-sourced/reconstructible;
- affected-consumer propagation is partial;
- host sessions can bypass repository contracts.

This repeatedly leaves the user as the missing scheduler.

## GOAL

Make ordinary Take-5 use satisfy:

Enter
-> Reconstruct
-> Discover
-> Select
-> Bind
-> Execute
-> Admit
-> Verify
-> Persist
-> Propagate
-> Regenerate
-> Reenter
-> Close/Open.

No material continuation requires the user to say "continue", name the next tool,
remind the system to search Research/web, or manually propagate the result.

## External comparison

Current outside architecture evidence reinforces rather than changes the recovered
direction:

- microkernel architecture supports a small trusted mechanism layer with richer
  services outside it;
- durable workflow architecture supports event-history reconstruction and explicit
  separation between orchestration and workers;
- current agent runtimes use explicit tools/handoffs, state, guardrails, and traces.

No outside comparator licenses copying its architecture wholesale.
