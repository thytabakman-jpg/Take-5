## E — EXPAND+OBSERVE / GDOS

### E1 KERNEL.yaml is not identical to mathematical K

The repository file KERNEL.yaml currently contains:
- semantic/kernel invariants;
- successor status metadata;
- development loop;
- promotion requirements;
- capability-generation references;
- recovery/admission orchestration references.

Therefore the artifact is a system/kernel manifest, not a pure realization of the mathematical role K.

This distinction was easy to miss while optimizing Take-5.

### E2 Kernel importance is not evidence for Kernel placement

Several globally important mechanisms remain correctly outside K:
- mode selection;
- capability routing;
- reconciliation algorithm;
- specialized tool delegation;
- runtime dispatch.

Kernel's job is to constrain legal transitions, not perform adaptive reasoning.

### E3 Experimental integrity is conditional rather than globally active

Potential invariants such as:
- frozen-target integrity;
- independent-observer isolation;
- no mutation before declared observation closure;
are relevant only when an episode declares an independent-observation regime.

They are better represented as conditional K contracts activated by an experiment/mode packet rather than unconditional global laws.

### E4 Capability-use coverage is a completion legality condition

"No silent capability bypass" belongs near K because it constrains what may count as legal continuation/completion.

The actual coverage scan and selector belong to controller/interface/runtime.

### E5 Mode itself is not a Kernel decision

Kernel may validate:
- declared mode;
- authority scope;
- isolation conditions;
- legal transitions.

Controller chooses:
EXPAND/CONTRACT and OBSERVE/ACT.

### E6 Tool-use resistance has a Kernel-relevant boundary but not a Kernel solution

Kernel can forbid false claims:
considered != selected != bound != delegated != executed != verified.

It cannot make IC delegate.
Delegation remains controller/interface/runtime behavior.

## F — CONTRACT+OBSERVE / focused resolution

Frozen discriminating question:

"What exactly must Kernel own for mode-sensitive capability orchestration to remain legal and truthful?"

Minimal focused answer:

K needs only the contracts necessary to preserve:
1. target identity/currentness;
2. protected invariants;
3. authority scope;
4. OPEN/incomparability;
5. declared observation-isolation/freeze commitments when activated;
6. execution-truth distinctions;
7. capability-coverage legality before material closure;
8. no self-promotion/self-authorization.

It does not need:
- mode policy;
- capability selector;
- reconciliation algorithm;
- tool semantics;
- local delegation algorithm;
- experiment scoring.

## EF — EXPAND -> RECONCILE -> FOCUS

EXPAND separated "important to the whole system" from "belongs in Kernel."

FOCUS then produced a smaller K obligation set.

Project payoff:
Take-5 can keep adding controller capabilities without bloating Kernel, provided K validates the legal transition envelope.

## Bias perturbation

Perturbation:
remove layer names such as Kernel, Controller, Interface, Runtime, Verification and present anonymous responsibility statements.

Observation:
most current placements remain stable.

Material residual:
the name KERNEL.yaml creates a mild naming bias because readers can infer that every field in the file is mathematically Kernel-owned.

Repair implication:
document the file explicitly as a successor-system manifest containing Kernel contracts plus adjacent orchestration metadata, or factor a pure K contract object later.

No immediate file split is authorized by this experiment alone.

## Project-specific payoff

1. New distinction:
repository KERNEL.yaml artifact != mathematical K role.

2. Mode-integrity constraints are conditional K contracts, not mode-selection logic.

3. Delegation truth belongs in the execution-truth boundary:
selected/bound/delegated/executed/receipted/reintegrated/verified.

4. Kernel can remain thin even as IC gains EXPAND/FOCUS/ACT orchestration.

5. New future test:
ablate the layer names and verify responsibility placement remains stable.
