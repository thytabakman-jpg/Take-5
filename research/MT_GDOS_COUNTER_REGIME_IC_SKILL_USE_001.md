# MT — GDOS Counter-Regime and IC Skill-Use Hypothesis 001

Date: 2026-09-24
Status: MATHEMATICAL CANDIDATE
Authority: research only

## Prompted hypothesis

Observed pattern:
- high endogenous outcome-pressure capabilities gain strongly from GDOS;
- low endogenous outcome-pressure capabilities such as typing, identity, provenance, and authority gain less.

Candidate counter-regime:
for low-pressure precision capabilities, performance may improve by deliberate narrowing rather than broad decoupling.

## 1. Two controller regimes

Define Broad Observation Regime B:

B(X;H) =
Freeze(X)
-> suppress G2 intervention pressure
-> expose X to plural observer basis H independently
-> defer mutation/reconciliation
-> reconcile observations.

Define Focused Resolution Regime F:

F(X,q;h) =
Freeze(X,q)
-> minimize admissible scope around discriminating question q
-> hold type/referent/criterion constant
-> apply one or a small coherent capability basis h recursively
-> stop at unique resolution, typed multiplicity, or OPEN.

B expands admissible observational support.
F contracts admissible resolution support.

They are dual with respect to search geometry, not opposites in purpose.

## 2. Expansion/contraction pair

Let A be the current admissible representation/search space.

Broad observation:
E(A) >= A under inclusion.

Focused resolution:
C_q(A) <= A.

Desired composition is not globally fixed.

For discovery-heavy/high-pressure tasks:
E -> reconcile -> C_q.

For precision/identity/typing tasks:
C_q may precede E, or E may be unnecessary.

Candidate controller law:

Mode(x) = argmin_mode expected information loss subject to task semantics.

Not a scalar utility claim; mode choice is typed.

## 3. Endogenous pressure coordinate

Define pressure p(h) as the degree to which capability h contains an intrinsic selector toward a preferred outcome before observation is complete.

This is not psychological pressure. It is structural selection pressure.

Candidate classes:
LOW: typing, identity, provenance, attribution, authority guard.
MEDIUM: relation, diagnosis, transfer, verification.
HIGH: generation, strengthen, repair, route, closure, ceiling search.

Hypothesis:
d Benefit_GDOS / d p > 0 over the current basis.

Counter-hypothesis:
d Benefit_Focus / d p < 0 for sufficiently low p and high precision demand.

## 4. Focused regime is not ordinary goal-directed optimization

Ordinary optimization:
select observations by usefulness to desired intervention.

Focused resolution:
reduce irrelevant degrees of freedom around a frozen discriminating question.

Thus:
Focus != GoalPressure.

Example typing:
not "which type helps the solution?"
but "which admissible type exactly fits this object's frozen semantics?"

## 5. Candidate Focused Resolution Sweep (FRS)

Pipeline:

FREEZE exact question q
-> TYPE admissible answer space
-> REMOVE irrelevant coordinates
-> SELECT discriminating capability
-> recursively tighten only result-sensitive unresolved coordinates
-> preserve multiplicity/OPEN
-> STOP when EX/UN status is resolved relative to basis.

FRS is a working name only.

## 6. Combination effects

Behaviors can produce irreducible joint effects.

For behaviors h_i,h_j define interaction residual:

IR(h_i,h_j|X,Mode)
=
Result(h_i ⊕ h_j)
-
Closure(Result(h_i),Result(h_j)).

Order residual:

OR(h_i,h_j)
=
Result(h_i∘h_j)-Result(h_j∘h_i).

Mode residual:

MR(h_i,h_j)
=
IR(...|B)-IR(...|F).

Therefore pairwise capability composition is mode-sensitive.

This extends the earlier quotient:
h_i ~_{J,Ctx,Mode} h_j.

## 7. Three-mode controller candidate

The evidence no longer supports only NORMAL vs OBSERVATION.

Candidate modes:

EXPAND
- broad frozen independent observation;
- best where premature selection threatens information loss.

FOCUS
- tight recursive discrimination;
- best where exact identity/type/provenance/criterion resolution is the job.

ACT
- goal-conditioned intervention, generation, repair, routing, implementation.

Candidate cycle:

EXPAND -> RECONCILE -> FOCUS -> ACT -> VERIFY -> [EXPAND or FOCUS or ACT]

Not every episode traverses every mode.

## 8. IC skill-use connection

Historical IC tool avoidance may have two distinct causes.

R1 missing selector/binding:
already identified and partially repaired.

R2 controller-mode mismatch:
IC's default behavior is broad integrative synthesis.
Specialized skills/tools often require local contraction:
freeze exact input,
honor the tool's narrow trigger,
delegate control to its transformation,
accept its result before reintegration.

A broad synthesis controller can semantically simulate the skill instead of crossing the contraction boundary needed to actually invoke it.

Thus the observed pattern may be:

IC broad mode
-> recognizes specialized capability
-> absorbs its semantics into global reasoning
-> fails to enter focused delegated execution mode
-> reports tool-like reasoning without tool execution.

This predicts skill avoidance even after a registry exists unless mode switching is explicit.

## 9. Skill invocation as authority transfer over local coordinates

Calling a specialized skill requires temporary local control transfer:

Global controller freezes:
- target,
- input,
- scope,
- authority,
- expected output contract.

Then specialized capability controls transformation within that envelope.

IC historically appears to retain transformation control rather than delegate it.

Candidate distinction:

USE_SKILL != REASON_WITH_SKILL_SEMANTICS.

USE_SKILL requires:
Bind + DelegateLocalTransformation + Receipt + Reintegrate.

## 10. Architecture implication

Kernel:
protects legal mode transitions, target identity, authority, OPEN, execution truth.

Controller:
selects EXPAND/FOCUS/ACT mode and capability composition.

Interface:
binds focused/delegated skill execution.

Runtime:
executes.

State:
stores mode, frozen packet, observations, receipts.

Verification:
tests both local skill contract and global reintegration.

No evidence yet supports putting mode-selection policy inside Kernel.
