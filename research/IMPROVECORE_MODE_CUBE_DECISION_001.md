## ImproveCore decision

Do not build one new tool per geometric region.

Build five capabilities because five distinct missing jobs survive reconstruction analysis:

1. DELEGATED EXECUTOR
Why:
known recurrent IC failure; no C-tool occupies CA-D.
Expected gain:
turn semantic skill recognition into actual bounded execution and faithful handback.

2. MODE ORCHESTRATOR
Why:
new mode geometry creates a routing problem not solved by ordinary capability selection.
Expected gain:
select EXPAND/CONTRACT, OBSERVE/ACT, DECOUPLED/COUPLED or sequences based on dominant information-loss risk.

3. RECONCILER
Why:
GDOS produces plural independent observations but current system has no explicit pre-action integration contract.
Expected gain:
preserve diversity while extracting common structure, conflicts, and interactions before optimization.

4. DISCRIMINATOR
Why:
precision behaviors are abundant but fragmented.
Expected gain:
convert typing/sensitivity/identity/focused recursion into one exact-resolution program without outcome pressure.

5. CAPABILITY CENTER FINDER
Why:
the user's "find the middle" operation generalizes across all capability sets and can prevent redundant tool creation.
Expected gain:
identify common protected function and residual distinctions for whole repertoire, quadrants, octants, or arbitrary subsets.

## New architectural lesson

Capability scarcity is not proportional to raw count.

CO-D has many tools because precision work was historically decomposed into many named checks.
CA-D has almost none because actual local delegation was not represented as a first-class protected behavior.

The count imbalance therefore reveals historical architecture bias, not merely inventory imbalance.

## Build order

1 Delegated Executor
2 Mode Orchestrator
3 Reconciler
4 Discriminator
5 Capability Center Finder

This order maximizes immediate execution gain first, then controller correctness, then observation workflow closure, then precision consolidation, then future toolkit design efficiency.
