## Round 3 — observe toolkit-wide consequences

Material observations:

R3.1
Not every atomic behavior needs its own recursive self-loop.

The wrapper belongs at the smallest episode boundary at which a material result/search delta can change continuation.

R3.2
This produces three recursion levels:

LOCAL
A tool internally recurses because its own semantics require iterative discovery.

PACKAGE
A composition reroutes/reorders children after material child returns.

CONTROLLER
Improvement Core recomputes work/capability/policy frontier after integrated state change.

These levels cannot be blindly nested at every call without recursion explosion.

R3.3
A child tool may close locally and return a typed delta to a parent.
The parent still must close package-level consequences before its next state.
The global controller still must reenter when integrated state changes.

R3.4
Therefore the generic wrapper needs explicit recursion ownership:
LOCAL_OWNER
PACKAGE_OWNER
CONTROLLER_OWNER
or SHARED with a declared handoff.

R3.5
The current Take-5 ProgramSpec lacks configured-run ownership and closure/reentry contracts.

R3.6
The current mode_selector prematurely encodes the four-quadrant hypothesis in runtime code.
That is an example of a candidate semantic result entering implementation before recursive/external challenge closure.

## External challenge — Architecture + Multi-Object view

Challenge question:
does the proposed wrapper fail when tools/packages are nested and interact?

Material finding EC1:
closure placement is order-sensitive.

A child's local closure may be insufficient when sibling interaction creates a new package-level consequence only visible after both children return.

Therefore:
LocalClosed(child_i) for all i
does not imply
PackageClosed(P).

Material finding EC2:
package-level closure cannot always be deferred to global controller closure because package order/interaction may alter the controller-visible result before handback.

Required hierarchy:

LocalConfiguredRun
-> PackageReconcile/Closure
-> ControllerIntegration/Closure
-> ControllerReentry.

Material finding EC3:
recursion ownership must also declare consequence scope:
LOCAL
CROSS_CHILD
GLOBAL.

Still supported:

- independence and deferred reconciliation matter;
- focused/narrow analysis can complement broad observation;
- tool-use execution truth matters;

Downgraded:

- five-tool build conclusion.

- configured-run identity;

- orchestration behavior as a protected migration target;
- wrapper-level external challenge;
- recursion ownership and consequence scope.

## Main result

The recurrent problem was not that individual tools were weak.

It was that tools were often invoked as semantic nuclei instead of as configured recursive programs.

The wrapper is therefore a cross-tool capability-preservation requirement, not an optional convenience.
