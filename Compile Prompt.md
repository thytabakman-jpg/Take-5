# Compile

## Governing objective
Reduce redundant files and information while preserving distinct substantive research, evidence, provenance, required functionality and dependencies. Compilation means actual elimination of approved redundant files, not creation of compatibility placeholders. The prompt owns the methodology; three independent operators perform bounded mathematical work. Do not invoke the Repair battery or bootstrap Take-5 merely to compile.

## Procedure

1. **Scope and freeze.** Verify repository identities, branches, commit SHAs and authorized targets. Distinguish candidate discovery from permission to delete. Inventory all potentially affected repositories, files, references, history and functional entry points. Record binary/unavailable/unsupported content and scope gaps. Recommendations-only requests do not write. Never modify unrelated files. Freeze the exact source and dependency snapshot and record authorization for each proposed retired file and each affected write.
2. **Discover and choose survivors.** Use document purpose, responsibilities, informational overlap, history and dependencies. Exact duplicates are candidates, not automatically redundant files. Retain functional navigation or compatibility surfaces where genuinely needed. Establish survivor paths and proposed final ownership before repairing links. Inspect material history; record immutable revision and source IDs.
3. **Consolidate losslessly and decompile.** Supply the complete admitted text snapshot as `{"files":{"owner/repo:path":"text"},"targets":["owner/repo:target.md"],"history":[{"id":"immutable source identity","text":"historical text"}],"maxPairs":50000,"threshold":0.7}`. Omit targets only for intentional whole-snapshot decomposition. Select all files being substantively changed or retired, not every unchanged dependency file. Run Decompiler. Keep the raw source occurrences, exact groups, candidate overlaps, and source spans. Do not interpret truncated candidate comparisons as exhaustive. A partial inventory or unsupported file is an explicit scope limitation.
4. **Layer and plan.** Group information by definitions, claims, evidence, inferences, mathematics, methods, architecture, historical information, unresolved questions and additional actual responsibilities. Classify each semantic unit within its structural source span; preserve attribution, qualifications and cross-layer relationships. Determine survivor sections and anchor mapping. Use temporary holding sections for unresolved information. No destructive edits yet.
5. **Prepare dependencies before material is moved.** Run Dependency with `{"mode":"prepare","before":FILES,"moves":{"owner/repo:old.md":"owner/repo:survivor.md"},"anchors":{"owner/repo:old.md#old-heading":"owner/repo:survivor.md#new-heading"}}`. Use returned `edits` as rebased original texts (keys are original sources); unchanged text comes from the frozen snapshot. Resolve OPEN mappings; retain source if ambiguous. This prevents losing relative-link context during merging. All mapped destinations must be established before coordinated repair. No writes occur in the operator.
6. **Deduplicate, synthesize, reconstruct.** Host resolves exact and semantic equivalence, subsumption, partial overlap and contradictions within layers, preserving all distinct material and source identity. Never infer semantic equivalence from similarity. Synthesize after layering; reorganize by actual responsibilities, not by original file. Preserve conflicting views as attributed positions. Historical material stays separate from current conclusions. Produce candidate snapshot, retired-file list, affected edits and per-unit preservation dispositions.
7. **Repair and audit.** Integrate prepared references into final texts; apply coordinated changes to incoming references, indexes, inventories, registries and manifests. Run Dependency in audit mode with the same before, moves and anchors, plus `after` candidate. Resolve reported issues and explicitly inspect unchecked references. A benign retired-path literal may be dispositioned with `literalReviews:[{source,target,contentDigest,reviewed:true,rationale}]`, using the exact issue digest and source-located evidence; do not use this for an operative or dangling reference. Independently search retired paths, filenames, encoded paths, section anchors, code/config references and cross-repository links not supported by the operator. Verify actual functional dependencies and run relevant tests. Do not ignore residuals merely because the destination exists. If scope or unsupported-reference coverage cannot be established, remain OPEN.
8. **Verify before publication.** Run Verifier with `before,after,decomposition,dependencyReport,history,dispositions,retire,allowedChanges,scopeReview`. The disposition map is keyed by unit ID. Exact: `{kind:"exact",target,start,end}`; semantic: same span with `kind:"semantic",reviewed:true,rationale`; historical: `{kind:"historical",reference:immutableGitHubBlobURL,reviewed:true,rationale}`; authorized removal: `{kind:"authorized-removal",reviewed:true,authorization,rationale}`. All offsets are UTF-16 code units. Unique literal spans in the same survivor or declared mapped survivor can be automatically matched; exact mechanical reference-only changes are checked against preparation output. Review these receipts for changed meaning or attribution; provide explicit dispositions where exact spans are not adequate. `scopeReview:{complete:true,evidence:"source-located coverage and functional test evidence"}` is allowed only after actual independent review of scope and unsupported references. A reported semantic review is not a proof. Maintain source provenance even for exact duplicates. Require READY_FOR_PUBLICATION plus actual semantic/functional evidence and no affected OPEN obligations.
9. **Publish safely.** Recheck frozen Git revisions and source identities. Use one guarded commit per affected repository (or isolated branch and PR if branch rules require); never overwrite intervening changes. Cross-repository publication is not atomic: coordinate ordering, avoid transient broken live paths, record partial publication and recover explicitly. Only delete approved files once replacement content and dependencies are ready. Re-fetch each committed snapshot and compare exact content. Re-run verifier with `publication:{revision,baseDigest,files}` for a single verified snapshot; record per-repository commit identities for multi-repository runs. Report only verified completion, exact retired paths, commit links, tests, residuals and any blockers. No redirect stubs count as elimination.

## Closure
Completion requires actual authorized deletions, preserved information and provenance, coherent ownership, repaired dependencies within admitted scope, independently verified functional consequences, and verified publication. The three operators never independently authorize destructive edits. Their finite outputs are evidence, not a substitute for semantic or operational review. No tool count, similarity score or partial result constitutes completion.
