## Current controller kernel

The current semantic kernel is:

DISCOVER -> PLAN -> REALIZE -> ADMIT -> INTEGRATE -> REENTER.

This supersedes the older flat control-cycle interpretation while preserving its protected behavior.

### DISCOVER

Co-generate live work, capability candidates, obligations, and coverage state. Work generation and capability generation are mutually constraining and reenter to a basis-relative fixed point. Generator-relative closure is explicit unless discovery completeness is independently certified.

### PLAN

Construct a state-indexed nondominated frontier of adaptive policies, not merely static capability sets. Planning accounts for semantic adequacy, executable realizability, authority, order/noncommutation, resources, continuation value, and current evidence. The frontier is recomputed after result-sensitive state/evidence changes.

### REALIZE

Bind selected policy actions to actual executable workers and execute them with explicit execution truth. Execution is represented as a versioned DAG/hypergraph carrying parent plan, nested capability calls, inputs, outputs, receipts, authority, state versions, and return edges. Semantic application is not implementation execution.

### ADMIT

Execution success does not imply result usability. Every returned result passes return admission for carrier/type, provenance, authority, scope, state-version compatibility, relevance, evidence quality, and work discharge. Stale, malformed, irrelevant, unsupported, or unauthorized results do not mutate governing state merely because execution occurred.

### INTEGRATE

Admitted results merge into evidence/state rather than blindly overwrite it. Supported conflicts remain typed. Persistent update distinguishes ephemeral state, persisted state, and canonically authoritative/current state. Material updates use transaction/recovery/idempotency semantics, an Orphan/Ghost consistency gate, and a mandatory Owner-Closure gate. Every material object must resolve to OWNED, SHARED_INTERFACE, OPEN_OWNER, ORPHAN_OWNER, or CONFLICT_OWNER before terminal claims are evaluated.

### REENTER

Verify, compute result-sensitive state/evidence/coverage delta, invalidate affected support, recover interrupted effects, rediscover/replan, or issue a typed terminal certificate. Verification itself is subject to the same execution/evidence discipline. Repeated behaviorally equivalent state without new evidence, coverage, intervention, or licensed search expansion is loop-blocked rather than counted as progress.

## Orphan/Ghost internal consistency kernel

Improvement Core applies the current directional support mathematics to its own state transitions.

Forward failure: a required material controller consequence lacks adequate persistent/current realization.

Reverse failure: active persistent/current state lacks adequate execution/evidence/authority grounding.

The current support semantics are obligation-relative and can use compatible multi-route support. Orphan/Ghost are job-, time-, basis-, and support-system-relative verdicts, not intrinsic permanent object properties.

Conflict covers incompatible supported alternatives where the job protects reconciliation/confluence. OPEN covers unresolved evidence or basis.

This protects artifact writes, dependency/current-state edges, expectation generation, propagation, authority changes, deletions/supersessions, verification obligations, and canonical pointers.

## Persistence and recovery
