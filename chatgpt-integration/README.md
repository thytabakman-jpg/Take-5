# ChatGPT Integration

This isolated integration branch packages the authoritative Take-5 **main** commit for a read-only, ephemeral ChatGPT Python execution environment. Use the authenticated GitHub connector and isolated local Python execution. GitHub Actions runners (paid, hosted or self-hosted) are not an execution prerequisite and must not be requested or triggered for Repair. An existing artifact is an optional source cache; when stale or unavailable, use the runner-independent reconstruction path below. If authenticated source reconstruction or required local validation cannot be completed, report OPEN/BLOCKED rather than claiming a successful bootstrap. No additional API key, model subscription, machine or scheduled job is inherent to the integration. The branch does not alter governing main or ICC-System.

2. Independently read the current `main` and `chatgpt-runtime-bootstrap` branch heads through the authenticated GitHub connector. 3. Within the same working environment, reuse an existing installed runtime and its successful bootstrap receipt when the independently resolved main and integration revisions, companion identities, and test environment are unchanged. The packet runner still revalidates the entire installed tree, integration companions, successful regression inventory, routing audit and recorded Python/dependency versions before imports; do not reinstall or rerun the bootstrap suite merely because a new compatible packet is dispatched. If the test environment or verification basis changes, repeat bootstrap certification. The recorded versions are observable invalidation coordinates, not a proof of complete environment identity; the host must also preserve the working environment and known result-sensitive configuration. If no reusable installation exists, reuse an existing verified packaging artifact if both revisions match. If stale, use it only as a cache of source bytes, not as current execution evidence. Do not dispatch a workflow, push a runtime-request file, purchase runner minutes or wait for a runner.
4. **Runner-independent reconstruction:** Obtain the current main commit's Git tree identity and commit object (or reconstruct exact commit-object bytes from authenticated Git metadata and accept only an exact commit hash match). Obtain a complete recursive tracked-tree manifest from the authenticated connector, or reconstruct it from a verified prior tree plus a complete change set, including deletions, additions and modes. Fetch changed/missing tracked blobs and current integration companions from the connector; verify every blob, including reused bytes, against the current manifest. If a cache is unavailable, obtain the complete tracked source directly. Reject truncated inventories, unsupported objects, missing bytes, unsafe paths and any root-tree or commit mismatch. Use the loader's local assembly mode after acquiring the authenticated identities and bytes: `python -B runtime_bootstrap.py <new-archive.zip> --expected-commit <main SHA> --integration-manifest <manifest.json> --destination <fresh directory> --receipt <receipt.json> --assemble-tree <git-tree.txt> --assemble-commit-object <source-commit-object.txt> --assemble-blobs <blob-directory> [--source-cache <old-archive.zip>]`. The NUL-delimited tree manifest uses `git ls-tree -r -z` format, and the blob directory contains fetched bytes named by exact Git blob SHA. The optional cache supplies only hash-matching bytes, indexed by Git blob identity rather than path; renamed and duplicate files reuse identical bytes. Use `cached_source_blobs(source_cache, tree)` from the independently verified loader to identify cached identities before fetching the remaining unique SHA-named blobs. The same invocation then installs and tests the assembled archive; the receipt records reused and externally supplied path counts separately from unique blob counts. These are local assembly counts, not a claim about actual connector requests. Record authenticated retrieval provenance separately; this offline helper does not fetch from GitHub itself. The archive is locally assembled, not an Actions artifact, and gains authority only from the unchanged loader's independent commit/tree/blob verification and local tests. If the exact Git object or complete tree cannot be recovered, preserve OPEN. Run with `python -B` (including direct diagnostic imports) and keep generated caches, receipts and packets outside the verified source tree. Independently recheck both branch heads before dispatch.
5. Before executing any packaged Python, independently verify the four companion bytes against the connector-fetched blob SHAs (Git blob SHA-1 is the hash of `b'blob ' + str(len(data)).encode() + b'\0' + data`). Reject missing, duplicate or mismatched archive members. Unpack the verified [bootstrap scripts](runtime_bootstrap.py) together, then run `python -B runtime_bootstrap.py <archive.zip> --expected-commit <main SHA> --integration-manifest <integration-manifest.json> --destination <fresh directory> --receipt <receipt.json>`. The loader also verifies the artifact integration commit and all four archived and local companion blobs against the independent manifest. The loader hashes the raw commit object against the independently fetched main SHA, reconstructs its root Git tree from the tracked-tree manifest, verifies every archived blob against that tree, checks the archive checksum, rejects missing or unsafe paths, runs native regression tests and the current configured routing audit, and writes a machine-readable receipt. Archives predating dual-revision verification require local reconstruction. A failed loader or missing dependency is OPEN/BLOCKED, not success. Source and test scripts are separate from host integration scripts.

## Read-only document-analysis bindings

### Provider responsibilities

[execute_tool_packet.py](execute_tool_packet.py) owns packet admission, provider authorization, dispatch and execution receipts. [document_tool_adapters.py](document_tool_adapters.py) owns both the built-in finite PD/PDAudit and syntactic Prose bindings and the specialized, explicitly selected document-analysis bindings described below. The two binding sets remain distinct: the runner loads its verified companion for built-ins without requiring an external module, while specialized bindings remain explicitly selected. Built-in receipt identity refers to the companion's verified blob. External replacements for a requested built-in require explicit per-tool override authorization. A provider failure does not prevent unrelated built-in tools from retaining their own execution dispositions.

The [integration regression suite](test_document_tool_adapters.py) exercises both binding sets against native implementations, including configured-gateway routing, bounded provenance and OPEN preservation. Run the suite locally against the verified native source and verified integration test bytes using `PYTHONPATH=<runtime>/runtime:<runtime>:<integration-directory> python -B -m unittest discover -s <integration-directory> -p 'test_*.py' -v`. Keep test sources and generated output outside the verified runtime. The local suite includes `test_document_tool_adapters.py` and `test_runtime_recovery_and_routing.py`; the historical manual packaging workflow is not required for Repair. Passing these checks establishes the tested integration behaviour, not general semantic coverage. When changing integration code, run the existing integration regression suite against the exact changed revision before certifying that change. The native bootstrap smoke suite and this integration suite certify different surfaces; a native bootstrap receipt alone is not evidence that integration regressions passed.

### Per-tool readiness diagnostics

Each packet result includes a `readiness_diagnostic` derived from the existing execution record, not a separate execution or certification. It distinguishes provider admission failures, input admission failures, reported native returns and unresolved execution stages; it exposes the configured disposition, recurrence status, adapter-specific blocker and batch blocker separately. A reported native return does not imply configured closure, independent verification or full semantic coverage. Unknown invocation provenance remains UNKNOWN. The existing tool results and receipts remain authoritative.

### Source-bound Prose review reports

The built-in Prose route accepts optional `prose.review_observations`: a mapping with `candidate_sha256` (UTF-8 text SHA-256), `contract_sha256` (canonical sorted-key JSON digest as computed by `document_tool_adapters.digest`), and `findings`. Each finding identifies a unique native `ProseEvidence` field, status (`OPEN`, `FAIL`, `REPAIR_REQUIRED`, `BLOCKED`, or `PASS`), source path and exact quote. The source must be current and its supplied UTF-8 bytes must match its declared Git SHA-1 blob. Candidate and contract digests must match. Native assessment consumes source-located adverse or unresolved findings; positive host PASS labels remain OPEN. The adapter returns the reported and admitted statuses separately. This route authenticates source bytes, not independent semantic judgement, and does not authorize a Prose PASS. A separately authorized independent semantic provider remains necessary for positive certification.

### Specialized bindings

The adapter implementation separates shared admission and finite-model operations, individual provider factories, and native provider selection. The provider selector binds only the selected model; native tool semantics, receipt scope and OPEN/BLOCKED requirements remain unchanged. The built-in and specialized public binding interfaces remain distinct.

[document_tool_adapters.py](document_tool_adapters.py) provides specialized host bindings for explicitly admitted classification matrices, finite integer-threshold comparisons, Architecture graphs and intervention frames, exact-quotation ASSERT evidence, structured Diagnosis/RTC evidence, source-revision currentness checks and open-obligation closure checks. It is recovered and verified with the integration companions. Run the existing packet runner with `--document-adapters` to select the verified companion explicitly; the equivalent `--adapter-module <integration-directory>/document_tool_adapters.py` remains supported. See [provider responsibilities](#provider-responsibilities) for the built-in binding and override rules.

Admission is per registered tool. A combined packet may supply multiple compatible input groups. Reuse the same frozen source evidence across separate packets when alternative routes conflict (for example, document observations or quotation claims and a finite matrix). Do not remove the ambiguity checks to force a native return.

Groups irrelevant to a tool's admitted routes are not validated. Alternative input groups for the same tool are not irrelevant: when both are present, admission rejects the ambiguity. Use scoped `tool_inputs` to combine compatible independent requests into one packet and share a single runtime-verification pass; preserve separate invocations where a real dependency requires a predecessor result or when alternative models conflict within one tool.

For a single packet containing incompatible model families, the verified companion supports a scoped form: `{"command":["GOAL","MultiObject"],"sources":[...],"tool_inputs":{"GOAL":{"document_observations":{...},"goal_candidates":[...]},"MultiObject":{"matrix":{...}}}}`. This is a schematic, not a complete executable example. In scoped form only `command`, shared `sources` and `tool_inputs` occur at the top level; each registered tool receives its own input object. Do not override shared sources or insert a second command within a route. A missing route is treated as missing tool input; malformed entries affect only their own tool. GOAL retains its actual internal MT prerequisite on the GOAL-specific evidence. Receipts retain the overall packet identity and, on a native return, the effective tool-input digest. The legacy flat packet remains supported. External provider modules must explicitly support this schema before receiving it.

Complete packet field definitions:
- `sources`: path, authenticated connector blob SHA (`sha`) and a subsequent independently fetched `latest_sha` for every source;
- `expected_ids`: authoritative inventory;
- `matrix`: `axes`, `raw` (one whitespace-separated case identifier and one slash-separated label field per axis per line), `transfer_fnv` (eight-digit FNV-1a over Unicode code points), `declared_counts`, `exclusive_axis`;
- `threshold`: nonempty unique source-supported integer `values`, inclusive integer `lower` and `upper` with lower ≤ upper, distinct integer `baseline_probes` within those bounds, nonnegative integer `declared_pair_count`, exact `proof`, `proof_fnv`;
- `open_coordinates`: unresolved source/semantic obligations; and optional `goal_candidates` (id, goal X/T/I/Sigma, constraints, evidence, grounded, authority_typed, determinate_enough).

GOAL's MT preflight is recovered from an actual gateway invocation. Only a matching projected configured disposition, HF002 recurrence, native gate evidence and exact packet identity can supply its MT receipt; raw labels from BLOCKED, CONFLICT, or resource-stopped execution do not license GOAL. MT runs a limited observation over the packet; unresolved semantic-stage bindings remain OPEN. MultiObject runs an independent algorithmic full-joint membership route before pair routes, then tests exact pair recoverability. It does not infer scholarly relationships from shared tags. ASSERT is the bounded compound core, not full-36 ASSERT certification. In the threshold route RTC tests additional probes in the fixed finite model; the structured route evaluates host-supplied candidates. Currentness verifies revision identity, not source truth. Prose requires separately evidenced semantic preservation, reader load and claim strength.

### Source-bound document observation input for MT and GOAL

For ordinary documents, use `document_observations` instead of the finite matrix/threshold route. Supply `target` (declared source path), and a nonempty `observations` array of objects containing `id`, `source`, exact `quote` and `interpretation` (explicitly host-derived). Every used source supplies exact UTF-8 `text`, Git blob `sha` and matching independently refetched `latest_sha`. Optional `previous` supplies the same target `path`, exact prior `text` and prior Git blob `sha`. The adapter verifies byte identities, quote presence, source currentness and evidence IDs, and computes zero-based, half-open changed line spans when a prior revision is supplied. These are exact textual comparisons, not independently certified material semantic deltas. Combining this route with a matrix or threshold is BLOCKED.

For GOAL, also supply `goal_candidates`: each has `id`, `goal` with `X`, `T`, `I`, `Sigma`, `constraints`, `evidence` (observation IDs), Boolean `grounded`, `authority_typed`, `determinate_enough`, and explicit `authority_basis` and `determination_basis`. Host semantic judgments remain host inputs. The provider uses the actual configured MT invocation as GOAL's prerequisite; a recovered goal is relative to the admitted candidates and does not certify the underlying document. Missing/stale inputs remain OPEN before invocation; malformed or contradictory source bytes are BLOCKED. Competing admitted goals remain OPEN. The document MT route always preserves `FULL_DOCUMENT_SEMANTIC_COVERAGE_OPEN`; its native gate does not claim the unbound black-box resolution stages were performed. For a specifically declared `open_coordinates` object, supply optional `semantic_pd_frames` mapping its ID to an explicit `pd_frame`. Every case must also include nonempty `evidence` observation IDs from the admitted document observations. The MT gate now invokes the existing built-in PD and PDAudit adapters through the actual configured gateway on that object's frozen frame, in the native pipeline order. Nested configured results are retained in `semantic_stage_runs`; a relative frame result is not a proved material semantic change. Missing MTA or subsequent stage bindings remain OPEN, and the global coverage obligation cannot be assigned a finite frame. GOAL retains the same configured MT prerequisite and its nested receipt. No automatic general document-semantic worker, independent evaluator, Architecture closure or TRC harvest completeness is introduced. The finite threshold/matrix route remains unchanged.

### Native source-reference analysis for Architecture and MultiObject

Use `source_relationships: {"paths":["a.md","b.md","c.md"]}` with the selected current sources (each includes `path`, `sha`, `latest_sha`, and exact `text`). Both tools share the frozen source basis; no classification matrix or manually declared graph is required. For Architecture, optional `dependency_path_roots` limits paths (default all selected paths). MultiObject requires at least three distinct paths and performs all unordered pair routes plus an independent full-joint route. The native extraction supports simple relative Markdown inline links and Python absolute import-name matches between selected paths. Ambiguous import matches, unsupported formats and Python parse errors are retained as unresolved; dynamic imports, external references, unparsed Markdown forms and semantic dependency completeness are outside this bounded basis. Findings include source/target revisions, line and token. Python import-name matches are possible references, never proof of execution. The graph adapter reports declared cycles and consumers; the MultiObject provider compares direct references, shared reference targets and cyclic components, then reconstructs its joint findings from independently computed pair facts. A cycle involving three objects is not automatically irreducible. Full relation semantics, ownership, result-sensitive dependencies, transformation admissibility and Architect's full directed scope remain OPEN. Do not combine this route with the alternative matrix, explicit graph or intervention model for the same tool.

### Explicit Architecture graph input

For Architecture alone, `architecture_graph` is an alternative to `matrix`; supplying both is BLOCKED. It contains a nonempty list of unique text `expected_units` and a `units` list. Each unit has a unique nonempty `id`, `source` path and exact Git blob `sha` matching a declared source, nonempty `role` and `locator`, and `internal_dependencies` (a list of unique text unit IDs). Optional `external_dependencies`, `information_ownership` and `execution_dependencies` are lists of declared text identities. Execution dependencies must be a subset of internal dependencies. The optional Boolean `check_unit_job_purity` enables the existing native `UNIT_JOB_PURITY` constraint; each unit then requires a nonempty `jobs` list of distinct identities and a nonblank `job_evidence` source locator. No exceptions or jobs are inferred from role labels. Source paths must be unique. Missing required fields remain OPEN; malformed fields are BLOCKED before the native entrypoint. Other tool bindings ignore this group.

The graph binding reports missing or unexpected units, dangling internal dependencies, reverse internal consumers, declared roles and ownership, and source provenance through the native Architecture core. `InteractionState.diagnostic_candidates` separately reports cyclic strongly connected components (including self-loops), cycles within explicitly declared execution edges, and multiple declared owners of a key. The optional `architecture_graph.dependency_path_roots` list selects declared unit IDs for deterministic shortest dependency and separately declared execution paths and potential transitive consumers. Omission requests no additional path analysis; missing/undeclared roots are rejected. Traversal excludes dangling targets and self-reachability. These are mechanical candidates and possible channels, not proof of causal impact, harmful execution cycles or incompatible ownership. When requested, the native unit-job constraint checks the explicitly declared job inventory; its blocker is retained. The host supplies and authenticates the graph facts; the adapter does not independently derive relationships or certify source truth, semantic ownership, external consumers or dynamic dependencies. The result intentionally retains OPEN for these unverified obligations, including on a structurally clean graph.

### Explicit Architecture intervention input

For Architecture alone, `architecture_interventions` is an alternative to `matrix` and `architecture_graph`; mixed models are BLOCKED. It requires unique nonempty `components` and `obligations` lists; `baseline_ids` (one observation per context); an `authority` evidence object; and `observations` (each with `id`, `context`, `state` in component order, `satisfied` obligation IDs, ordered `protected` projection and `evidence`). Each evidence object contains `source_path`, `source_sha`, `locator` and `basis` matching an admitted source. Optional `candidates` have an `id` and `observation_ids` covering all baseline contexts. The runtime uses explicit observations only. It evaluates witnessed minimal supports, isolated-coordinate dependencies, joint effects relative to a union-of-newly-satisfied-obligations algebra, protected-projection preservation and nondominated observed gain. Candidate authorization, unobserved interventions, continuation equivalence and full directed coverage remain OPEN; no mutation or full Architect certification follows. This route requires a main revision containing the finite provider. The source locator is a host declaration, not independent proof that an intervention was executed.

### Exact quotation ASSERT input

For ASSERT, `assert_quotes` provides an alternative to the matrix and threshold model; supplying either finite-model group alongside it is BLOCKED. It contains a nonempty `claims` list of unique nonempty text `id`, `source` path and nonblank exact `quote`. Sources use the existing list, with unique paths and valid Git blob SHA; additionally supply exact UTF-8 `text`, independently refetched `refetched_text`, and `latest_sha` for each available source. Do not normalize whitespace, Unicode or line endings. SHA-1 and SHA-256 Git blob identity are supported.

The seven-stage native compound ASSERT checks exact substring presence against the frozen text and then the refetched bytes. TRUE and FALSE report correspondence; unavailable evidence or an invalid frozen text/hash match is UNKNOWN, and a changed revision or inconsistent refetched text/hash match is CONFLICT. Malformed inputs are BLOCKED; false or unresolved claims prevent closure. The adapter verifies supplied bytes against supplied hashes but cannot authenticate the host's fetches, establish independent model evaluation, test paraphrases or infer semantic support for a claim.

### Structured Diagnosis and RTC input

These bindings also accept an explicit evidence inventory instead of a threshold model; a matrix is not required. Use top-level `diagnosis` with `failures`, or `rtc` with `candidates`. Each object includes nonempty `inventory_evidence`; a deliberately empty inventory is allowed only with that evidence. Each row has a unique nonempty string `id` and nonempty `evidence`. Every evidence list consists of objects with `source_path`, `source_sha`, `locator` and `basis`. The path and exact lowercase Git blob SHA (40 or 64 hexadecimal digits) must match an entry in `sources`. Locators identify the relevant passages; basis explains the observation or inference. Source authentication and semantic interpretation remain the host's responsibility.

- Diagnosis rows contain an optional Boolean `material` and an optional textual `mechanism`. Null or absent mechanism remains unresolved; a non-null mechanism requires `mechanism_evidence`.
- RTC rows contain `strict_gain` and `preserves`, each Boolean or null (absent is unresolved). For each explicit Boolean, supply the corresponding `gain_evidence` or `preservation_evidence`.
- Do not include a threshold model in a packet invoking a structured route for the same tool: ambiguity is BLOCKED. Missing evidence stays OPEN. A mixed RTC result retains both admitted candidates and unresolved candidates, and its adapter disposition remains OPEN.
- The provider validates the declared evidence references and input types, then invokes the original native tools. It does not independently authenticate the references, establish the proposed mechanism, prove gain/preservation or authorize edits. The receipt is bounded to the supplied inventory. Other tools retain their original input requirements.

### Source-bound candidate and claim analysis

The following optional document routes consume explicit host-supplied evidence rather than requiring a threshold model. Every route has `inventory_evidence` and unique row IDs with nonempty `evidence`, using the same source-path, blob-SHA, locator and basis objects as Diagnosis/RTC. Do not mix a candidate route with a threshold model for the same tool. Unknown or unsupported conclusions remain OPEN.

- **Discriminator:** `candidate_evidence` contains a nonempty `predicate` and `candidates` with `id`, `decision` (MATCH, NO_MATCH or UNKNOWN) and evidence. Native filtering retains UNKNOWN candidates; only a unique evidenced match with no unknowns can close relative to the declared candidate set.
- **Reconciler:** `reconcile_claims.claims` contains `id`, a nonempty `key`, a scalar `value` (string, integer, Boolean or null for unknown) and evidence. Exact typed values are compared per key; incompatible values and unknowns remain OPEN. This does not certify general semantic equivalence.
- **RootCause:** `root_cause` contains `basis_id`, a nonempty `failure_class` and `candidates` with `id`, native `level`, `explains` (failure IDs), evidence and optional `upstream_of` (candidate IDs), `unresolved`, `counterevidence`, `causal_test_evidence` and `rival_discrimination_evidence`. The flags `survives_representation_change` and `removal_breaks_recurrence` default to false; true requires its corresponding `<flag>_evidence`. The native HF2 procedure assesses the supplied candidates; absent causal tests or unresolved rivals are not filled in by the adapter.

These bindings validate source identities and declared evidence structure, not the truth of host judgments or completeness of the candidate inventory. They do not replace the native mathematical contracts or independent verification.

### Worker contract mapping and execution provenance

The worker contract defines semantic obligations rather than a common Python ABI. This bounded, read-only integration maps them as follows.

| Contract field | Existing representation or boundary |
| --- | --- |
| Frozen target and corpus | Tool-specific packet contents, source paths/blob identities and locators; host verifies source extraction. Built-in finite PD/Prose packets carry explicit model/text, not independently authenticated source evidence. |
| Typed state and continuation basis | Gateway state, selected native input schema and configured HF002 receipt; no independent persistent research state or upstream obligations inferred. |
| Capability and provider | Exact registered ID and configured plan; runner records integration manifest, built-in or explicit module identity and packet digest. |
| Authority | Read-only host analysis; no promotion or research writes authorized by the receipt. |
| Result and evidence | Native result and evidence, source references where supplied, adapter provenance and bounded scope; source truth and semantic coverage are not certified. |
| Execution truth and open obligations | Gateway disposition, recurrence receipt, native result and adapter blocker; `adapter_provenance.native_invocation` distinguishes RETURNED from NOT_INVOKED for these supplied bindings. Missing/untrusted provider evidence is not upgraded. |
| Target effect and proposed state delta | Findings only; existing material-delta semantics and unchanged research state. No implicit mutation or promotion. |
| Verification and continuation | Native checks, source-specific evidence, recurrence receipt and explicit remaining obligations; independent semantic verification and any missing affected-scope coverage remain OPEN. |

A native return marked OPEN or BLOCKED is distinct from an admission failure before invocation. The gateway's normalized execution truth remains authoritative for closure, while the separate adapter provenance records whether the native call returned. Exceptions with uncertain execution phase remain UNKNOWN. External providers remain responsible for their own execution evidence. A binding or a recorded return alone is not SEMANTICALLY_APPLIED or FULL_MATCH.
