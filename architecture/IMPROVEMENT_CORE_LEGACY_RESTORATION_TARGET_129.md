## Governing user goal

Recover the material mathematics, ideas, distinctions, failed paths, prompts, project state,
and discoveries from the recent ChatGPT conversation/file corpus; restore the ImprovementCore
behavior that the user experienced as fast, self-directed, context-aware, and aligned with the

The archive is evidence and recoverable memory. It is not the active prompt.

## Core distinction

FULL_HISTORY_AVAILABLE
does not imply
FULL_HISTORY_LOADED_INTO_EVERY_RUN.

The target architecture has two layers.

### Durable recovery corpus

The recovery corpus preserves:
- exact source identity and path;
- content hashes;
- duplicate/equivalence relations;
- conversation chronology where available;
- files and generated artifacts;
- mathematics/equations;
- accepted, rejected, superseded, OPEN, and historical ideas;
- provenance links into canonical reconstructed objects.

Nothing material disappears merely because it is not loaded into the active controller state.

### Lean active controller

The active controller retains only continuation-relevant state and retrieves corpus evidence when
a live question, object, dependency, provenance issue, or reconstruction need makes that evidence
material.

This preserves the Legacy behavior instead of turning archival completeness into context bloat.

Meaning:

E:

## Required restored behavior

A restored ImprovementCore must demonstrate all of the following on unlike holdouts.

1. REAL-GOAL RECOVERY
It infers the governing job from evidence instead of requiring the user to script tool order.

2. ENDOGENOUS INQUIRY
Unresolved structure generates the next material question/discriminator.

3. PROBE GENERATION
Questions generate concrete evidence/tests/distinctions capable of changing the candidate space.

4. MINIMAL ADEQUATE ROUTING
When one cheap capability/package preserves the protected job, broader machinery is not run merely
because it exists.

5. PLURALITY
Incomparable live routes remain plural until evidence licenses a choice.

6. RESULT-SENSITIVE RESELECTION
Material evidence, representation, search, authority, or capability change causes affected
frontier recomputation.

7. NO PREMATURE STOP
Completing a work package is not controller completion while live admissible inquiry remains.

8. INTERNAL AUTONOMY
The controller asks the user only for genuine user authority, unavailable personal facts,
preferences, or inaccessible external dependencies.

9. MEMORY WITHOUT BLOAT
Historical evidence is retrievable and provenance-linked without placing the whole corpus in
ordinary active state.

10. EXECUTION TRUTH
Selection, binding, execution, result use, verification, and completion remain distinct.

11. ANTI-LOSS
A material discovery receives durable provenance/disposition before it can disappear from the
governed system.

12. RESPONSE DISCIPLINE
Internal machinery is not dumped into the user-visible answer unless the user asks for it.
The controller returns the useful result, decision, unresolved blocker, or next genuine question.

## Corpus use rule

When the master three-month archive becomes available:

1. bind the exact archive identity;
2. inventory every member and byte-accounting surface;
3. preserve paths and hashes;
4. deduplicate by content without deleting duplicate provenance;
5. extract text/structured content;
6. preserve binary/unreadable members as unresolved rather than losing them;
7. reconstruct conversations chronologically where the export permits;
8. extract candidate equations, tool definitions, prompts, discoveries, decisions, failures,
   accepted/rejected alternatives, and project state;
9. compare recovered candidates with current canonical state;
10. promote only strict gains or historically required restorations;
11. retain superseded/history-only items as provenance;
12. rerun the Legacy behavioral benchmark.

## Anti-churn rule

A new repair is licensed only by one of:

- a failing protected behavioral benchmark;
- newly recovered historical evidence that changes the target;
- an execution/currentness/provenance break at a claimed boundary;
- a material project task exposing a real controller failure.

A new file, wrapper, audit, or tool name is not itself evidence that more repair work is needed.

Repeated unchanged repair routes are NO_GAIN.

## Completion condition

The restoration episode reaches RELATIVE_CLOSE when:

- the available three-month corpus has complete source/member accounting;
- every recovered material candidate has a typed disposition and provenance;
- the active controller passes the Legacy behavioral benchmark on heterogeneous holdouts;
- current protections are preserved or explicitly replaced by witnessed strict gains;
- no known live restoration residual remains;
- remaining inaccessible host/account data is typed as an external boundary rather than an
  internal repair obligation.

At that point ordinary project work resumes.
Future controller work reopens only from the anti-churn triggers above.
