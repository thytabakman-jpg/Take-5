# Wrapper Term PD 064

Date: 2026-09-25
Status: CURRENT DISTINCTION RECORD

## Question

What distinct objects have been compressed into the load-bearing term "wrapper"?

## Distinctions

1. Tool wrapper
   Orchestration local to a protected native tool run.

2. Canonical system wrapper
   The ordered math-first control spine that binds observation, formalization, freezing, goal recovery, architecture, routing, execution, closure, update, Jane synchronization, HF1, and reentry.

3. Geometry wrapper
   The typed geometry expansion placed around a stage or tool. It is not itself the canonical system wrapper.

4. Response wrapper
   The pre-emission boundary that classifies formal objects, preserves mathematical status, applies glyph-level color, and rejects raw HTML or other bypasses.

5. Historical wrapper
   A preserved prior version used for provenance, regression comparison, or recovery.

## Rule

The bare word "wrapper" is admissible only when exactly one of these objects is recoverable from local context.

Otherwise the term remains unresolved and must be qualified.

## Consequence

The earlier sentence "every component runs through its full 36-dimensional wrapper" conflated geometry and orchestration. A valid statement must identify both the wrapper role and the geometry type.
