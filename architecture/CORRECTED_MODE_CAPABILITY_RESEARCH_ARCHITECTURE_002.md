# Architecture Analysis — Corrected Mode-Capability Research Plan 002

Date: 2026-09-24
Status: RESEARCH ARCHITECTURE / CORRECTED PLAN
Authority: research only

## 0. Correction basis

This architecture analysis explicitly incorporates the MT critique of the prior plan.

The following are NOT treated as established:
- that Breadth x Direction x Coupling is the minimal or complete mode space;
- that Coupling is the uniquely correct third axis;
- that the eight octants are orthogonal;
- that primary-mode counts establish real underrepresentation;
- that five new capabilities are already justified;
- that octant centers exist or are unique;
- that the proposed build order reflects measured leverage.

The architecture therefore separates:
HYPOTHESIS
EXPERIMENT
MODEL COMPARISON
CAPABILITY RECONSTRUCTION
CANDIDATE BUILD
RUNTIME VALIDATION
ADMISSION.

## 1. Top-level architecture

The corrected program is:

OBSERVED PHENOMENA
-> CANDIDATE COORDINATES
-> COMPETING MODE MODELS
-> FACTORIAL / HOLDOUT EXPERIMENTS
-> CAPABILITY-MODE CLASSIFICATION
-> RECONSTRUCTION / ABLATION
-> GAP DISPOSITION
-> CANDIDATE CAPABILITY BUILD
-> RUNTIME TEST
-> ADMISSION.

No capability is built merely because a geometric cell exists.

## 2. Research layers

### Layer R0 — Frozen empirical phenomena

Protected observations already motivating the program:
- GDOS sometimes exposes material structure hidden by goal-directed reasoning;
- independence and delayed reconciliation sometimes alter results;
- focused/narrow analysis appears useful for some precision tasks;
- IC has repeatedly selected or reasoned about skills without proving actual delegated execution;
- sequential mutation can change what later observers see.

These are phenomena, not yet an accepted geometry.

### Layer R1 — Competing representation models

At least these models must coexist:

M2:
Breadth x Direction.

M3-C:
Breadth x Direction x Coupling.

M3-I:
Breadth x Direction x Independence.

M3-U:
Breadth x Direction x MutationTiming.

M3-D:
Breadth x Direction x Delegation/LocalAutonomy.

Continuous model:
breadth, directionality, coupling/independence represented as graded rather than binary coordinates.

Alternative-factor model:
mode inferred from information-flow and control-transfer variables rather than named axes.

Architecture rule:
do not let M3-C govern tool design until it outperforms serious alternatives on holdouts.

### Layer R2 — Operational definitions

Every candidate axis must have:
- observable input condition;
- manipulation protocol;
- result-sensitive output;
- independence from the other candidate axes sufficient for factorial testing.

Example:
"coupling" cannot merely mean independence + shared-state mutation + delegation all at once.

Operational decomposition candidates:
- sibling-output access;
- shared-state read access;
- shared-state write access;
- feedback during run;
- local transformation autonomy;
- mutation timing.

These may prove to be separate axes.

### Layer R3 — Experiment design

Minimum experiment families:

E1 factorial manipulation:
vary breadth, observe/act direction, and one candidate third coordinate independently where possible.

E2 competing-model prediction:
each representation predicts outcomes on frozen unseen tasks before results are revealed.

E3 cross-domain holdout:
Kernel, Canonical Authority, Core Mathematics plus at least one structurally different project.

E4 classification reliability:
multiple independent classification passes over B01-B58/C01-C49 or rule-based classifier agreement.

E5 causal delegation test:
explicit delegated specialist execution vs semantic simulation, with same frozen local task.

E6 reconciliation test:
independent observations -> explicit reconciler
versus
RELATE+RECONSTRUCT composition
versus
ordinary synthesis.

E7 focused-resolution reconstruction:
coherent Discriminator candidate
versus
typing+sensitivity+recursive narrowing composition.

E8 center-existence test:
determine whether a nontrivial common protected core exists in each candidate region.
Allow:
UNIQUE_CENTER
MULTIPLE_INCOMPARABLE_CENTERS
TRIVIAL_CENTER
NO_CENTER
OPEN.

## 3. Capability classification architecture

Do not use one primary octant as the authoritative representation.

For every capability h store a mode profile:

Profile(h) = {
supported_modes,
preferred_conditions,
failure_modes,
information_access,
state_access,
mutation_access,
delegation_status,
order_sensitivity
}.

Primary-mode labels may remain a visualization only.

Counts are descriptive and cannot by themselves establish architectural gaps.

## 4. Gap detection architecture

A mode region is a genuine capability gap only when:

G1 repeated material job exists;
G2 current repertoire cannot reconstruct that job under licensed composition;
G3 ablation shows protected loss;
G4 holdout shows the gap affects unseen tasks;
G5 proposed capability closes the loss;
G6 gain survives comparison with cheaper composition/configuration;
G7 runtime execution is demonstrated.

Therefore:

EMPTY_CELL != GAP.

LOW_COUNT != GAP.

REPEATED_FAILURE + NONRECONSTRUCTIBILITY + HOLDOUT_GAIN -> GAP_CANDIDATE.

## 5. Candidate capability statuses

### Delegated Executor
Status:
HIGHEST-PRIORITY GAP HYPOTHESIS.

Reason:
historical tool-use failure plus apparent lack of explicit bounded local autonomy.

Still required:
- prove existing binding/delegation components do not reconstruct it;
- run real execution vs semantic-simulation experiment;
- test faithful reintegration.

### Mode Orchestrator
Status:
MODEL-DEPENDENT CANDIDATE.

Do not build final selector until mode representation stabilizes.

Near-term version:
experimental mode router that records alternative mode candidates and grounds rather than claiming one correct mode.

### Reconciler
Status:
IRREDUCIBILITY OPEN.

Test against:
RELATE + RECONSTRUCT + interaction residual + provenance preservation.

Only build as distinct capability if this composition loses protected behavior or is materially inferior.

### Discriminator
Status:
IRREDUCIBILITY OPEN.

Test against:
typing + result sensitivity + invariant localization + focused recursion + relative closure.

### Capability Center Finder
Status:
RESEARCH METHOD CANDIDATE.

Before building:
define partial order / meet conditions;
allow no-center and plural-center results;
test whether MTA/PD already reconstructs the function.

### GDOS
Status:
OBSERVED REGIME CANDIDATE.

Formalize protocol for experiments.
Do not treat its cube coordinate as settled.

### Improvement Core
Status:
CONTROLLER UNDER TEST.

Do not assign it permanently to one mode region.
Instead measure its mode profile and mode-switch behavior.

## 6. Corrected architecture placement

Kernel K:
- preserve target/currentness;
- authority boundaries;
- execution truth;
- declared isolation/freeze contracts;
- OPEN/incomparability;
- no self-promotion;
- no false delegation/execution claims.

Kernel does NOT:
- define the correct mode axes;
- choose a mode;
- choose tools;
- decide whether a new capability exists.

Controller:
- run experimental mode selection;
- preserve alternative mode hypotheses;
- route capabilities;
- switch modes with recorded grounds.

Epistemic layer:
- compare competing mode models;
- run classification;
- perform center/reconstruction analysis;
- bias/perturbation testing.

Interface:
- bind candidate capabilities;
- establish exact local scope and authority for delegation.

Runtime:
- execute real bound capabilities.

State:
- record mode/model used;
- frozen target;
- observations;
- mutation history;
- delegation/execution/reintegration receipts.

Verification:
- test predicted gain;
- test protected behavior;
- compare with baseline/alternative models;
- holdout and ablation.

## 7. Build architecture

Do not start with five production-quality tools.

Phase A — instrument:
1. formal GDOS protocol;
2. focused-resolution protocol;
3. delegation execution receipt;
4. mode/profile logging;
5. reconciliation packet format.

Phase B — discriminate:
1. run competing-mode experiments;
2. classify capabilities with profiles;
3. run reconstruction tests for Reconciler/Discriminator/Center Finder;
4. run real delegation experiment.

Phase C — build only survivors:
- build Delegated Executor if nonreconstructible and causally useful;
- build Reconciler if composition loses protected information;
- build Discriminator if coherent program yields material gain;
- build Center Finder if mathematically nontrivial and not MTA/PD duplicate;
- build Mode Orchestrator only after model comparison supports stable routing coordinates.

## 8. Scientific stopping criteria

The representation is ready to govern architecture only when:
- candidate axes are operationalized;
- competing models have been tested;
- predictive holdout evidence exists;
- classification reliability is acceptable;
- at least one causal intervention supports the proposed mechanism;
- continuous vs discrete representation has been compared;
- important effects replicate across domains.

A capability is ready to build only when:
- job is repeated and material;
- current repertoire fails reconstruction;
- protected loss is demonstrated;
- candidate closes it;
- cheaper composition does not.

## 9. Corrected priority

Immediate:
1. delegation experiment;
2. third-axis discriminator experiment;
3. Reconciler reconstruction test;
4. focused-resolution reconstruction test;
5. capability profile schema;
6. competing-model holdout.

Deferred:
- full eight-octant taxonomy;
- center-per-octant claims;
- global Mode Orchestrator;
- capability count conclusions;
- build-order claims based on expected leverage alone.

## 10. Architectural conclusion

The prior plan jumped too quickly from an interesting geometric representation to a build architecture.

The corrected architecture is:

DISCOVER PHENOMENA
-> COMPARE REPRESENTATIONS
-> TEST CAUSAL COORDINATES
-> PROFILE CAPABILITIES
-> PROVE FUNCTIONAL GAPS
-> BUILD ONLY SURVIVORS.

The strongest near-term candidate remains delegated execution, but even that is a test target, not yet an admitted new capability.

The mode cube is now demoted from architecture to a competing research model until it earns governance over tool design.
