# ICC128 Host Relay Contract

Status: IMPLEMENTED REPOSITORY SURFACE
Date: 2026-10-03
Canonical runtime: runtime/icc_entry.py::run_icc
Relay surface: runtime/icc_host_relay.py::relay_icc128

## Purpose

The host relay makes ICC128 the substantive owner of an ICC-governed user turn.

Intended transport path

user
-> host transport
-> relay_icc128
-> canonical ICC128 runtime
-> ICC-authored user response
-> host transport unchanged
-> user

The host may transport bytes, authenticate the caller, expose the endpoint, and
render the returned response. The host does not generate a replacement answer,
reinterpret a failed tool run as success, or substitute host reasoning while
claiming an ICC result.

## Fail-closed rules

The relay returns OPEN, BLOCKED, or CONFLICT when the canonical ICC runtime does.

A successful relay result requires all of the following.

1. The request is bound to ICC128.
2. The canonical run_icc surface executes.
3. The runtime closes relative to its governing episode.
4. The ICC128 controller result itself contains icc_user_response before closure.
5. Closure and update preserve that exact response.
6. host_fallback_used remains false.
7. The relay returns that ICC response unchanged.

Missing runtime bindings do not license semantic imitation.

Missing configured-tool adapters do not license prose substitution.

A host-authored fallback cannot be labeled an ICC response.

## Integrity receipts

Every relay result records the request id, controller identity, relay basis,
SHA-256 of the exact request payload, runtime status, relay status, typed blocker
when open, SHA-256 of the exact ICC response when complete, and explicit
host_fallback_used state.

These receipts distinguish transport from substantive authorship.

## External host boundary

The repository now owns a fail-closed relay interface. Universal interception
inside an arbitrary chat host remains external until that host connects to this
surface.

Repository relay implemented is therefore distinct from external host connected.

Once a ChatGPT connector, MCP bridge, or equivalent external transport calls this
surface, the host can act as a transport layer while ICC128 remains the
substantive controller. Until that connection exists, ordinary ChatGPT turns are
not evidence that this relay executed.
