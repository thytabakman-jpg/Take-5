## Governing question

Which recovered lineage best satisfies the user's actual target:

a cumulative autonomous research/improvement system that can recover the real problem,
discover work the user did not pre-enumerate, select and execute real capabilities,
preserve verified gains, revise its own representations and controller when evidence
requires it, and continue until relative closure without requiring repeated user prompts?

The decision is behavioral, not repository-prestige based.

## Choice

Do not select one repository unchanged.

Adopt this successor architecture:

Take-5 remains the canonical working substrate.

The target controller/regime becomes a cumulative autonomous ImprovementCore whose
behavior is reconstructed from the strongest strict-gain lineage across all five corpora.

The successor must combine:

1. Take-2 kernel discipline.
2. Take-3 architecture-admission discipline.
3. Take-4 cumulative autonomous problem/reselection behavior.
4. Reaserch's latest high-effectiveness ImprovementCore semantics and IC-030 manager recurrence.
5. Take-5's validated wrapper, identity, closure, reentry, authority, provenance,
   currentness, and execution safeguards.

## Successor behavioral contract

The target operating regime must support:

Observe/black-box entry
-> recover/freeze current object, state, authority, and governing goal
-> upstream discovery when the correct job is not yet warranted
-> co-generate live questions, work, and capability candidates
-> select nondominated executable continuation
-> bind and execute real workers
-> admit results
-> reconcile/integrate/persist verified consequences
-> invalidate stale plans and dependencies
-> verify
-> regenerate inquiry/work/capability frontier
-> automatically reenter at the earliest invalidated stage
-> preserve learning/no-gain/failure memory
-> stop only at relative closure or typed OPEN/BLOCKED/CONFLICT.

## Transition law

For every material change:

old protected behavior
-> exact lineage comparison
-> strict-gain / duplicate / conflict / historical-only / OPEN disposition
-> authorized transition
-> validation
-> currentness propagation
-> reentry.

No source repository self-promotes by being newer.
