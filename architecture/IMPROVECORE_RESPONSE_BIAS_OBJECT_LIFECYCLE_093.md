Date: 2026-09-26
Status: IMPLEMENTED CANDIDATE
Parent workstream: PR 76 / ImproveCoreAfterRun
Regime candidate: 093

## Problem

Three recurring losses shared the same transition defect:

1. the user repeatedly preferred a particular ImproveCore response behavior, but the preference was not an operational release contract;
2. system and input-framing biases could alter selection before independent observation/currentness checks;
3. newly discovered ideas/projects/tools could become load-bearing before durable semantic lifecycle capture.

A report-only repair would reproduce the defect.

## Response preference contract

Every governed ImproveCore after-run now carries the current response profile.

Protected projection:
- result first;
- actual actions rather than intended actions;
- parent controller owns continuation after explicit required entry steps;
- material delta regenerates work;
- material results persist before closure;
- executed and analyzed remain distinct;
- OPEN/BLOCKED/CONFLICT remain visible;
- current object identity is exact;
- final release is concise and material.

Preference does not have truth authority.

Evidence/currentness/execution status can override a preferred presentation or desired conclusion.

## Bias control

Every governed after-run receives a bias audit receipt.

System-side guards cover:
- host substitution;
- familiar-tool selection;
- recency/currentness;
- action/closure pressure;
- architecture preservation;
- tool salience;
- goal leakage;
- self-audit expressivity;
- internal brute force.

Input findings are framing risks, not personality diagnoses.

Correction policy:
- preserve explicit required entry steps;
- otherwise treat framing as evidence;
- observe/currentness-check before goal-conditioned compression;
- generate rival framings;
- separate preference from truth authority;
- preserve typed OPEN/BLOCKED/CONFLICT;
- acquire/reuse existing capabilities before rebuilding;
- reselect after material delta.

## New-object lifecycle

Managed kinds:
IDEA, PROJECT, TOOL, META_TOOL, PROGRAM, SEMANTIC_OBJECT, TERM.

Prospective semantic package:
CORE.md
+ MANIFEST.md
+ 36 directed scope-transition pages.

Thus the recovered package has 38 required semantic pages.

Unknown coordinates remain explicit OPEN.

PROJECT adds typed bootstrap obligations:
portfolio registration, identity/kind, orientation, state home, provenance/authority home,
task-entry route, unfinished-work route, capability inheritance.

IDEA adds:
preserve source, type/relate, explicit disposition, and no promotion to project/tool without a typed transition.

TOOL/META_TOOL/PROGRAM additionally retain the existing mathematics-complete-for-use admission requirement.
